一、安装 ADB：macOS 与 Windows

ADB 包含在 Google 的 Android SDK Platform-Tools 中。建议始终使用最新版；Google 说明新版工具向后兼容，独立下载包同时提供 Windows、macOS 和 Linux 版本。

macOS：使用 Homebrew

brew install --cask android-platform-tools
adb version

没有 Homebrew 时，也可以从 Google 官方页面下载 macOS 版 Platform-Tools，解压后在该目录运行 ./adb。

Windows：官方 ZIP 方式

  1. 下载 platform-tools-latest-windows.zip。
  2. 解压到固定目录，例如 C:\platform-tools。
  3. 在该目录打开 PowerShell；或把该目录加入系统 Path。
  4. 运行下面的命令验证。
cd C:\platform-tools
.\adb.exe version

# 仅对当前 PowerShell 会话加入 Path（可选）
$env:Path += ";C:\platform-tools"
adb version
提示：Windows 无线 ADB 不需要额外 USB 驱动；只有使用 USB 调试时，部分品牌设备才可能需要 OEM 驱动。

二、在电视上开启无线调试

  1. 电视与电脑连接同一个局域网。
  2. 进入“设置 → 系统 → 关于”，连续点击“版本号”约 7 次。
  3. 进入“开发者选项 → 无线调试”，打开开关并允许当前网络。
  4. 记下主页面显示的 IP 地址和连接端口。
  5. 打开“使用配对码配对设备”，保持页面不退出，记下临时的 配对端口和 6 位配对码。
不要公开配对码。它虽然会过期，但发布教程或截图时仍应打码；设备 GUID、MAC 地址和公网信息也应隐藏。

三、最大坑：配对端口 ≠ 连接端口

项目本次示例出现位置对应命令有效期
配对端口40975“使用配对码配对设备”弹窗adb pair临时；退出页面可能变化
连接端口43733无线调试主页面adb connect本次无线调试会话

先配对，再连接。为避免把配对码写进 Shell 历史，建议让 ADB 交互式询问：

# 第一步：使用“配对端口”
adb pair 192.168.50.195:40975
# Enter pairing code: ******

# 第二步：使用“连接端口”
adb connect 192.168.50.195:43733

# 验证
adb devices -l

成功后会看到类似：

192.168.50.195:43733  device  product:BRAVIA_AE2_CN  model:BRAVIA_4K_AE2
如何自动发现两个端口？

电视停留在配对页面时，可用 ADB 的 mDNS 浏览；macOS 还可使用系统自带的 dns-sd：

adb mdns services

dns-sd -B _adb-tls-pairing._tcp local.
dns-sd -B _adb-tls-connect._tcp local.
典型报错：把连接端口用于 adb pair，常见结果是 protocol fault；把配对端口用于 adb connect，则可能立即断开，或在配对页面退出后失效。

四、真实故障排查记录

1. 先确认电视和端口可达

# macOS / Linux
ping -c 2 192.168.50.195
nc -vz -w 3 192.168.50.195 43733

# Windows PowerShell
Test-Connection 192.168.50.195 -Count 2
Test-NetConnection 192.168.50.195 -Port 43733

2. nc 能连，但 ADB 报 “No route to host”

本次在 macOS 上遇到：普通 TCP 测试成功，ADB 后台进程却被本地网络隐私控制拦截。优先进入“系统设置 → 隐私与安全性 → 本地网络”，允许当前终端或执行 ADB 的应用，然后重启 ADB：

adb kill-server
adb start-server
adb connect 192.168.50.195:43733
高级备用：仅在 ADB 进程被拦截时使用本机 TCP 转发

让 Python 访问电视，ADB 只连接回环地址。用完立即按 Ctrl+C 关闭。

# tcp_proxy.py
import socket, threading

LISTEN = ("127.0.0.1", 43734)
TARGET = ("192.168.50.195", 43733)

def pipe(src, dst):
    try:
        while data := src.recv(262144):
            dst.sendall(data)
    finally:
        try: dst.shutdown(socket.SHUT_WR)
        except OSError: pass

def relay(client):
    upstream = socket.create_connection(TARGET)
    a = threading.Thread(target=pipe, args=(client, upstream), daemon=True)
    b = threading.Thread(target=pipe, args=(upstream, client), daemon=True)
    a.start(); b.start(); a.join(); b.join()
    client.close(); upstream.close()

with socket.create_server(LISTEN) as server:
    while True:
        client, _ = server.accept()
        threading.Thread(target=relay, args=(client,), daemon=True).start()

# 运行 python3 tcp_proxy.py
# 然后 adb connect 127.0.0.1:43734

3. APK 大文件安装时设备变为 offline

如果使用自制转发器，不能用“非阻塞 socket + 直接 sendall”粗略转发大文件，否则缓冲区可能出现 Resource temporarily unavailable。上面的双线程阻塞式转发可避免此问题。

五、确认现有 AirPlay 到底是谁提供的

macOS 可以直接浏览局域网的 AirPlay 与 RAOP（音频）服务：

dns-sd -B _airplay._tcp local.
dns-sd -B _raop._tcp local.
dns-sd -L '乐播投屏（BRAVIA 5）' _airplay._tcp local.

本次解析结果显示，“乐播投屏（BRAVIA 5）”来自电视，AirPlay 服务端口为 52244。ADB 进一步确认包名与服务：

# macOS / Linux
adb shell "pm list packages | grep -Ei 'airplay|hpplay|cast'"
adb shell "dumpsys activity services | grep -Ei 'AirPlayService|hpplay'"

# Windows
adb shell pm list packages | findstr /I "airplay hpplay cast"

检测到的付费应用包名是 com.hpplay.happyplay.aw。检查系统包后，没有发现原生 Chromecast 接收包；Wi‑Fi Display/Miracast 也没有可直接启用的完整接收能力。因此需要安装独立、合法的开源接收器。

六、安装开源 AirPlay Server

采用 F-Droid 收录的 AirPlay Server，包名 io.github.jqssun.airplay。它基于 UxPlay，支持 Android TV、H.264/H.265 镜像以及 AAC/ALAC 音频。本文测试版本为 0.0.31，包含电视所需的 armeabi-v7a 原生库。

下载来源：优先从 F-Droid 应用页取得当前版本，不要从不明 APK 站下载。本文测试 APK 的 SHA-256 为 c5dce5c29ab52157bdaa406e485f9bfaab7d8d59c523d93622a33b253a28f410。
adb install -r io.github.jqssun.airplay_31.apk

adb shell monkey -p io.github.jqssun.airplay \
  -c android.intent.category.LEANBACK_LAUNCHER 1

adb shell dumpsys package io.github.jqssun.airplay | grep -E 'versionName|versionCode'
adb shell dumpsys activity services io.github.jqssun.airplay

启动后，电视出现“Waiting for connection…”，新的接收器名称为 Android AirPlay。再次浏览 mDNS：

dns-sd -B _airplay._tcp local.
dns-sd -L 'Android AirPlay' _airplay._tcp local.
nc -vz -w 3 192.168.50.195 7000

确认免费接收器工作后，可逆停用乐播

# 停用乐播：不卸载、不清数据
adb shell pm disable-user --user 0 com.hpplay.happyplay.aw

# 需要恢复时
adb shell pm enable com.hpplay.happyplay.aw
这不是破解。没有修改乐播 APK、付费状态或服务器校验，只是使用另一个开源接收器，并可逆地停用原应用。

同时验证：乐播原端口 52244 已拒绝连接；开源接收器端口 7000 正常开放。此后在 iPhone、iPad 或 Mac 的“屏幕镜像”菜单中选择 Android AirPlay 即可。

DRM 限制：Netflix、Apple TV+ 等受 FairPlay/DRM 保护的内容通常无法通过开源接收器镜像。这是内容保护限制，不是安装失败。普通桌面、照片、网页和非 DRM 视频可正常使用。

八、安全收尾与日常使用

  • 调试完成后运行 adb disconnect 和 adb kill-server。
  • 不再需要远程维护时，关闭电视的“无线调试”。
  • 在“已配对设备”列表中可以随时忘记电脑，撤销 ADB 信任。
  • 不要在路由器上把 ADB 端口映射到公网。
  • 开源接收器建议开启 PIN，避免同一局域网内的陌生设备误投。
